# CLAUDE.md

Guidance for AI assistants (and new contributors) working in this repository.
This complements `README.md` — read that first for the project overview.

## What this is

The Cyicaro Farm website: a bilingual (EN/FR) React 18 + Vite 7 single-page app,
exported from Hostinger Horizons, laid out as an npm-workspaces monorepo. The
only workspace today is `apps/web`.

## Commands

Run from the **repo root** unless noted:

```bash
npm install                                    # install workspace deps
npm run dev                                     # dev server (port 3000)
npm run build                                   # build → dist/apps/web
npm run lint                                    # ESLint

# Target the web workspace directly:
npm run <script> --prefix apps/web
# IPv4 dev host (if `--host ::` fails with EAFNOSUPPORT in a container):
npm run dev --prefix apps/web -- --host 0.0.0.0
```

Node 22 is required (`.nvmrc`).

## Architecture & conventions

- **Entry flow:** `src/main.jsx` mounts `src/App.jsx`. `App.jsx` owns the
  `Router`, the `EditProvider`, the persistent `Header`/`Footer` layout, and the
  `<Routes>`. Add new routes there.
- **Path alias:** import from `@/…` (maps to `apps/web/src/`), e.g.
  `import { Button } from '@/components/ui/button'`. Configured in
  `vite.config.js` and `jsconfig.json`. Prefer it over long relative paths.
- **Pages** (`src/pages/`): one component per route. Each page sets its own
  `<Helmet>` title/description and pulls copy through `t('…')`.
- **Components** (`src/components/`):
  - `components/ui/` — shadcn/ui primitives (Radix-based). Managed via
    `components.json`; treat as generated. Prefer reusing these over hand-rolling
    new primitives.
  - top-level `components/` — domain components (`Header`, `Footer`,
    `ActivityCard`, `TeamMember`, …).
- **Styling:** Tailwind utility classes only; no CSS modules. Use the design
  tokens (`bg-background`, `text-foreground`, `border-border`, `primary`, …)
  defined as HSL CSS variables in `src/index.css`. Brand color is **emerald**,
  neutrals are **stone**. Merge conditional classes with `cn()` from
  `@/lib/utils`.
- **Animation:** `framer-motion` (`motion.*`, `whileInView`) — follow the
  existing fade/slide-up pattern used across pages.

## Internationalization — the important rule

**All user-facing copy must go through i18n.** Never hard-code display strings
in JSX.

1. Add the key to **both** `src/i18n/locales/en.json` and `fr.json` (keep the two
   files structurally in sync — same keys in both).
2. Read it with `const { t } = useTranslation();` then `t('section.key')`.
3. Top-level sections: `nav`, `home`, `about`, `whatWeDo`, `nos_activites`,
   `activitiesPage`, `donate`, `footer`.

Language is persisted in `localStorage.language` and switched from the header.

## The Horizons visual editor (dev-only)

- `apps/web/plugins/` holds Vite plugins that power the Horizons editor. They
  load **only** when `NODE_ENV !== 'production'` (see the `isDev` guard in
  `vite.config.js`). Don't rely on them at runtime in production, and generally
  don't edit them unless the editing tooling itself is the task.
- `src/contexts/EditContext.jsx` toggles an in-browser edit mode: elements marked
  `data-editable="true"` become `contentEditable` and edits are saved to
  `localStorage` (they do **not** write back to the translation files). When
  adding editable text, keep the `data-editable="true"` attribute pattern.
- The `session-journal` plugin writes `vault/temp/SESSION_JOURNAL.md` during dev
  runs. `vault/` is git-ignored — do not commit it.

## Do / don't

- **Do** keep changes inside `apps/web` unless you're intentionally changing the
  monorepo tooling.
- **Do** run `npm run lint` and `npm run build` before committing; both must pass.
- **Do** add new dependencies to `apps/web/package.json` (the app workspace), not
  the root, unless they're build-orchestration tooling.
- **Don't** commit `node_modules/`, `dist/`, or `vault/` (all git-ignored).
- **Don't** hard-code copy — use i18n (see above).
- **Don't** hand-edit generated files: `package-lock.json`, `public/llms.txt`
  (regenerated by `tools/generate-llms.js` on build), or `components/ui/*` beyond
  what shadcn/ui expects.
- **Note:** `src/pages/HomePage.jsx` is an unused empty stub; `Home.jsx` is the
  live home page. Remove or repurpose the stub rather than duplicating it.

## Dead-code analysis

`knip.json` (root) configures [knip](https://knip.dev/) for finding unused files,
exports, and dependencies. Useful before large cleanups.
